## 2. Упаковка — три мода MO2

| Мод MO2 | Содержимое | Место в списке |
|---|---|---|
| `Anomaly Coop - Engine` | `bin\AnomalyCoopDX11AVX.exe` + gamedata нашей ревизии движка (наш форк modded exes) | **самый низ** (наименьший приоритет): перекрывает только `E:\Anomaly\gamedata`, а моды GAMMA, правящие скрипты modded exes, остаются поверх |
| `Anomaly Coop - Core` | скрипты, конфиги, интерфейс коопа (`coop_*`, DLTX `mod_*.ltx`, modxml/DXML) | наивысший |
| `Anomaly Coop - GAMMA` | декларации и патчи под моды GAMMA (`coop_compat_*`), наш обвес интерфейса | наивысший: выше Core (последняя строка левого списка MO2), чтобы патчи под GAMMA могли перекрыть файл Core; ставится только с опцией «G.A.M.M.A.» |

В левом списке MO2 сверху стоит наименьший приоритет, в `modlist.txt` — наоборот. Поэтому порядок задаём словами
MO2: Engine — Send to… → Lowest priority (верхняя строка списка). Core, затем GAMMA — Send to… → Highest priority
(две нижние строки, GAMMA последней).

- Один архив (`tools/package.ps1` → `releases\anomaly-coop-<версия>.zip`). Верхние папки архива — три готовых мода
  MO2: `Anomaly Coop - Engine\` (`bin\`, `gamedata\`), `Anomaly Coop - Core\gamedata\`, `Anomaly Coop - GAMMA\`
  (`gamedata\` из `gamedata_gamma\` репозитория, пока пусто, и `readme_gamma.txt`). Рядом лежит `fomod\`.
- **FOMOD за одну установку создаёт один мод MO2.** Поэтому архив ставится по разу на часть: на Anomaly — 2 раза, на
  G.A.M.M.A. — 3 раза. Шаги установщика:
  1. «Ваша игра» (Anomaly 1.5.3 / G.A.M.M.A.).
  2. «Часть» (Engine / Core / GAMMA). Имя мода игрок вписывает в поле Name окна установщика.
  3. Для Engine — способ запуска exe.
  4. Для Core — дополнения.
  5. На G.A.M.M.A. для Core и GAMMA — список модов к выключению из `docs/MOD_REPLACEMENTS.md`.
  6. «Последний шаг» — своя страница на каждую часть.

  Другой путь — распаковать три папки в `<MO2>\mods` и нажать F5.
- Не проверено в настоящем MO2:
  - вложенное `Or` внутри `<visible>`;
  - `destination=""`;
  - поле Name.

  Это проверка «раз за фазу» вместе с владельцем.
- exe под своим именем: лаунчер GAMMA его не трогает (есть). Инструкция «после обновления GAMMA» — проверить, что

- Файлы Core и GAMMA никогда не перекрывают стоковые и чужие скрипты целиком: только `coop_*`, DLTX, modxml/DXML,

## 3. Стенд разработки на профиле GAMMA

Две копии игры через USVFS MO2 на одной машине ненадёжны. Поэтому стенд **материализуется** (сделано в Ф1):
- `tools/deploy.ps1 -Profile G.A.M.M.A` собирает корень `E:\AnomalyCoopGamma`, MO2 берёт из `-Mo2Dir E:\GAMMA`.
  Сам стенд строит `tools/mo2_stand.py` (можно вызвать отдельно, `--help`). Слои снизу вверх:
  1. Игра `E:\Anomaly`, без её `appdata`.
  2. Engine: наш exe в `bin\` (через `temp\stand_engine`) и `engine\gamedata`.
  3. Включённые моды профиля по `modlist.txt`.
  4. `overwrite`.
  5. Core (`gamedata`).
  6. GAMMA (`gamedata_gamma`, если папка есть).

  Пути сравниваются без учёта регистра. `meta.ini` в корне мода и `*.mohidden` не берутся.
- Файлы модов — жёсткие ссылки (тот же том `E:`). Если ссылка невозможна, сборка падает с `hardlink impossible`;
  тихого копирования нет. **Копируются**, а не связываются, места, куда игра и скрипты GAMMA пишут на ходу:
  - корень стенда (MCM дописывает `fsgame.ltx`);
  - `appdata\`;
  - корень `gamedata\`;
  - корень `gamedata\configs\` (`axr_options.ltx`, кеш 3DSS лежит прямо в моде);
  - `bin\*.ini|.log|.txt` (ReShade).

  Иначе запись ушла бы в оригинал мода GAMMA. Наши слои всегда копии: репозиторий на другом томе. Существующий
  файл стенда никогда не перезаписывается: сначала удаляется, потом создаётся заново. `launch.ps1` пишет
  `axr_options.ltx` так же.
- Пересборка инкрементальная, по манифесту `.mo2_stand.json`. Файлы, которых стенд не создавал (`appdata_a`, `bin_b`,
  `fsgame_a.ltx`), он не трогает. Писать через junction и в папку слоя отказывается.
- `db\` — настоящая папка ссылок, а не junction: моды кладут в неё `db\mods\*.db0`. `bin_b` — ссылки на всё из
  `bin`. Файлы `appdata\` модов копируются в `appdata_a/_b`. `fsgame_a/_b.ltx` берутся из `fsgame.ltx` стенда.
- `tools/launch.ps1 -GameDir E:\AnomalyCoopGamma` запускает хоста и клиента. `-NoStart` всё готовит и печатает
  команду, игру не запускает. `-NewGame` берёт `new_game_loadouts.ltx` стенда (GAMMA: `G.A.M.M.A. Starting
  Loadouts`), DLTX-добавки не применяет.
- Отчёт стенда пишется в `temp\mo2_stand_report.txt`. В нём:
  - число модов и файлов (ссылки, копии, без изменений, удалено);
  - время;
  - моды без папки;
  - источники, изменившиеся с прошлой сборки (так видна и запись игры через ссылку);
  - топ-20 конфликтов: путь, число слоёв, последние слои, победитель последним.
- Раз за фазу — проверка в настоящем MO2 (`ModOrganizer.exe` с нашим exe) вместе с владельцем.

## 4. Политика по модам GAMMA

- Чужие файлы не правим и не удаляем.
- **Выключаем** мод, если его механику забрал движок или она противоречит коопу. Работает инструкция в FOMOD и
  проверка при запуске: наш Lua видит включённый конфликтный мод → пишет предупреждение в лог и чат и
  нейтрализует его хуки.
- **Урезаем** мод, если движок забрал часть: декларация `none` для его колбэков (`docs/MOD_LAYER.md` §2.2).
- Каждое выключение или урезание — строка в `docs/MOD_REPLACEMENTS.md` в том же коммите.
- Отпечаток модлиста при входе сравнивает наборы и показывает понятный список отличий (есть, доработать текст).
