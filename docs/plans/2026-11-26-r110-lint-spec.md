# R110 lint specification

Every rule of `docs/CODE_RULES.md` whose check is a lint. Written 2026-11-26 against the tree of that day (mod `master`,
engine `coop`). Rule ids on the right of each entry are `docs/CODE_RULES.md` ids. The one-line summary of every check, with
its package, is `docs/CODE_RULES.md` section 14; this file holds the exact patterns and the catch / pass sets.

Numbering: one id is one check, ids are never reused. "L2 extension" adds patterns to the existing L2 and keeps its id.
Plan steps of `docs/plans/2026-11-18-two-modes.md` are always written "step S2", never bare "S2". `Pn` alone is a package of
the R107 cleanup plan; a TZ principle is always written "principle Pn".

## 0. Common contract (TOOL-9)

Every check below follows these rules.

- **Two homes.**
  - `tools/check_layers.py`: the layer and mod-knowledge rules (L*). It already has the tree model, the layer map
    (`tools/layers.txt`), the Lua and C++ tokenisers and the allow-list.
  - `tools/check_static.py` (new; created by package P2, which per the R107 backlog adds "new check rules with today's
    ceilings"; the cleanup packages lower the ceilings and P35 finishes the ratchet): hygiene rules (S*). It imports
    `check_layers.collect`, `cpp_code`, `lua_code`, `decode`, `parse_allow` and `format_allow`, so there is one tree model
    and one allow-list format. It must not grow a second parser; `tools/check_actor_compare.py` is the anti-pattern.
- **Who runs it.** G (`tools/check_gates.py`), T (`tools/run_all_tests.cmd`, once per run) and `tools/release.py verify`.
  T calls each checker once (today `check_layers` runs twice per T, see TEST-6).
- **Allow-list.** A finding is the line `rule|path|code of the line, comments dropped, white space collapsed|count`.
  - Files: `tools/layers_allow.txt` (exists, `# ceiling: 342`) and `tools/static_allow.txt` (new, its own `# ceiling:`).
  - `--write-allow` may only shrink a list. A new line needs `--write-allow --reset-ceiling`, which the lead runs and which
    `test_layers.py` / `test_static.py` refuse in a gate run.
  - The ceiling is the sum of counts; it only goes down.
  - Every allow-list row is today's debt, taken when the rule is added (never copy counts from this file: re-measure at
    implementation time).
- **Kinds.**
  - `refuse`: no allow-list rows, a hit fails.
  - `ceiling`: today's rows frozen, a new hit or a higher count fails.
  - `warn`: printed, with its own ceiling.
- **No in-code exemptions** (`layer-ok`, `noqa`). An exception is a path or a pattern in the checker, named in this file.
- **Comments and strings.** Unless an entry says "in comments" or "in strings", patterns run on code with comments and
  string contents blanked (`cpp_code(text, keep_strings=False)`, `lua_code`). C++ scope is `engine/src` without
  `3rd party`, unless the entry narrows it.
- **Tests.** Each rule gets a catch / pass set as fixture files under `tests/tools/fixtures/layers/` (L*) or
  `tests/tools/fixtures/static/` (S*), driven by `tests/tools/test_layers.py` / `tests/tools/test_static.py` (new):
  - every bad example must be reported with its rule id;
  - every good example must not be reported;
  - a ceiling test checks that a fixture tree with one extra hit fails and one fewer passes with a lower written ceiling.

  The real tree is checked by G, never by a unit test.
- **Paths below.**
  - Lua scope `coop_*.script` always means `gamedata/scripts/coop_*.script` plus `gamedata/scripts/modxml_coop_*.script`;
    `gamedata_gamma/scripts/coop_*.script` is included too.
  - "Core Lua" means a Lua file whose layer in `tools/layers.txt` is core (adapters `coop_mods_*` are core for the mode
    rules).
  - "Common Lua" means core Lua that is not `coop_mods_*`, plus the srv and hostplay layers (MOD-2, R113).
  - "Adapter" means `coop_mods_*.script`: core for the mode rules, a modpack set for naming (it may name its own mod and
    call `coop_mods_core`).
