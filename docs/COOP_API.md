# Anomaly Coop — API для мододелов (v1, 2026-10-23)

Как мод работает в коопе и что ему для этого даёт движок. Сначала — слой модов без единой строчки патча
(`docs/MOD_LAYER.md`): одинаковый модлист у всех, маршрутизатор колбэков, маршрутизатор вызовов, зеркало `m_data`,
декларации в ltx. Lua-API `coop.*` и `coop.sync` — **крайний случай**: тонкий патч мода, когда всего этого мало.
Свой сетевой протокол поверх `coop.send_event` патч не строит.

Всё ниже проверено юнит-тестами и Lua-тестами на заглушках; в игре — по мере живых прогонов (задача 25).

## 1. Пространство `coop`

Есть всегда, и в одиночной игре тоже. Функции с аргументами — простые C-функции: неверный аргумент даёт `nil` /
`false` и причину, а не ошибку Lua.

### 1.1 Сессия и игроки
| Функция | Что даёт |
|---|---|
| `coop.is_active()`, `is_host()`, `is_client()`, `is_live()` | есть ли сессия; эта машина хост; клиент; в мире (хост или клиент после загрузки) |
| `coop.self_id()` | свой id игрока: хост — 0, клиенты — 1..7 |
| `coop.players()` | `{ {id, nick, avatar_id, rtt, is_self}, ... }` |
| `coop.avatar_of(peer)`, `coop.peer_of_avatar(id)` | персонаж игрока и обратно, в нумерации этой машины |
| `coop.owners_known()` | клиент уже знает, кто играет каким персонажем |
| `coop.to_host_id(id)`, `coop.to_local_id(id)` | перевод id объекта между нумерацией хоста и своей (у клиента меняются местами 0 и id его персонажа) |
| `coop.life_of(id)`, `coop.bleed_left(id)`, `coop.player_safemode(peer)` | состояние игрока: жив / ранен / мёртв, остаток кровотечения, оружие опущено |
| `coop.talk_holder(npc)` | хост: кто сейчас говорит с NPC |
| `coop.session_info()`, `coop.host(port)`, `coop.connect(addr)`, `coop.disconnect()`, `coop.host_when_ready(port)` | меню коопа |

### 1.2 Деньги (F2 T1, T6b)
Баланс игрока хранит хост. `coop.money_give(peer, n)` — свои деньги другому игроку (хост проверяет). У хоста:
`money_grant(peer, ±n)`, `money_set(peer, n)`, `money_of(peer)`, `talk_lock_of(peer)`. Ответ — `ok, why`.
- `coop.money_set_rules(enabled, max)` → `ok, why`. **Только хост**: правила переводов между игроками (опции
  `money_transfer` и `max_money_transfer`).
  - `enabled` — строго `true` / `false`; `max` — число от 0 до 4294967295, лимит одного перевода в RU, дробь режется к
    нулю (0 — переводов нет). Не хост — `false, "host only"`, неверный аргумент — `false, "bad arguments"`.
  - Журнал хоста отказывает в переводе против этих правил, что бы ни проверил Lua клиента.
  - Зовёт наш `coop_economy_money.script` у хоста: каждые 2 с и сразу при смене опции. Правила живут весь процесс, новая
    сессия их не сбрасывает; пока вызова не было — переводы включены, лимита нет. Моду звать не нужно: его вызов
    перезапишется следующим толчком.
- Колбэк `coop_money_note(kind, peer, amount, why, cause)` — что хост сделал с деньгами игрока. Движок зовёт его на машине
  того, кого это касается (подарок хосту — на хосте). Колбэк объявляет `coop_economy_money.script`
  (`AddScriptCallback`); мод подписывается обычным `RegisterScriptCallback("coop_money_note", fn)` в `on_game_start`.
  - `"received"` — другой игрок дал вам денег. `peer` — дарящий, `amount` — зачисленные RU, `why` и `cause` — `nil`.
  - `"refused"` — хост не принял изменение вашего баланса. `peer` — получатель, если это перевод (`cause == "transfer"`),
    иначе `-1`. `amount` — запрошенное изменение: минус — трата или перевод, плюс — доход.
    `why` — причина по-английски: `"not enough money"`, `"over the allowance"`, `"over the maximum"`,
    `"transfers are off"`, `"over the transfer limit"`, `"malformed"` (у перевода — получателя нет в игре).
    `cause` — `"script"`, `"dialog"` или `"transfer"`.
  - Отказы приходят только клиенту и не чаще одного за 3 с, подарки не режутся. Заметка, пришедшая до входа клиента в
    мир хоста, отбрасывается.

### 1.3 Прочее
- `coop.send_event(name, payload, target)` → `coop_main.on_event(name, payload, from)` на получателе. **Устарело**:
  новые патчи берут `coop.sync`. Клиент шлёт события не быстрее, чем хост их принимает (F2 T14, Ruling F2-14): лишнее
  ждёт в очереди, а не теряется; `false, "queue full"` — только когда переполнена сама очередь (512).
- `coop.stash_set(key, value)` / `coop.stash_get(key)` — строки этой машины на всю сессию, переживают загрузки уровней.
- `coop.spot_is_local(type)`, `coop.story_hold_infos(on)`, `coop.story_local_task(id[, on])` — сюжет и метки, которые не
  уходят хосту.
- `coop.explode_as(...)` — заряд взрывается от имени того, кто его поставил.
- `coop.route.*` — маршрутизатор колбэков (`coop_router.h`); моду он нужен только через ltx (§3).

## 2. `coop.sync` — общие данные, действия через хост, эффекты (SYNC_SPEC §6)

### 2.1 Кто решает
- **Хост** держит хранилище и ставит каждому изменению версию из одного растущего счётчика.
- **Клиент** держит копию того, что хост ему шлёт, и просит хост о своих изменениях. Своё изменение клиент видит
  сразу, до ответа хоста. Хост отказал — значение возвращается к хостовому, и `on_change` об этом сообщает.
- **Одиночная игра** (сессии нет) работает по правилам хоста, без сети. Мод на `coop.sync` в одиночке работает так
  же, и его данные так же лежат в сейве.

### 2.2 Области
| Строка | Что это | Кто пишет | В сейве хоста | Кому уходит |
|---|---|---|---|---|
| `"world"` | общее для мира | хост | да | всем |
| `"session"` | общее на время сессии | хост | нет | всем |
| `"player"` | данные своего игрока | он сам и хост | да, по ключу игрока | только ему |
| `"player:<peer>"` | данные подключённого игрока (только у хоста; у клиента — только свой id) | хост | да | только ему |
| `"object:<id>"` | данные объекта или предмета, id в своей нумерации | хост и тот, кто держит предмет | да | всем |
| `"object"` | все объекты — только для `on_change` | — | — | — |

- Область игрока привязана к **ключу игрока**, а не к id персонажа или подключения. Игрок перезашёл или сейв дал
  его персонажу другой id — данные те же (Ruling F2-24).
- Данные объекта едут с ним: писать их может только тот, кто держит предмет сейчас. После передачи предмета прежний
  владелец получает `false, "not allowed"`. Объект уничтожен — его область удаляется у всех.
- Движок переводит id объекта в имени области (`object:<id>`) между нумерациями. **Значения он не переводит**: id
  внутри значения — в нумерации той машины, что его записала. Кладите в значения id хоста (`coop.to_host_id`) или
  не кладите id вовсе.

### 2.3 Значения и лимиты
- Значение — `nil` (удаляет ключ), число (конечное), строка, `true`/`false`, `vector`, плоская таблица.
- В таблице ключи — строки или целые индексы до 2^53 (массив вернётся массивом), значения — число, строка, bool,
  `vector`. Таблица в таблице не принимается.
- Ключ — 1..128 байт. Значение — не больше **16 КиБ** в закодированном виде: `false, "value too large (N > 16384)"`.
  Крупные данные игрока идут через зеркало `m_data` (F2 T15, T20), не через `coop.sync` (Ruling F2-25).
- Лимит на область: world 4 МиБ, session 1 МиБ, player 1 МиБ, object 64 КиБ. Каждый ключ стоит ещё 64 байта, каждое
  поле таблицы — 32 байта.
- Лимит на число областей: 256 игроков и 65 536 объектов, у всех вместе 16 МиБ. Переполнение — `false, "scope full"`.

### 2.4 Функции
Отказ всегда возвращает `false, why` (или `nil, why`), ошибку Lua не бросает.

| Функция | Что делает |
|---|---|
| `set(scope, key, value) -> true \| false, why` | меняет значение, если этой машине можно |
| `get(scope, key) -> value` | значение или `nil` (таблица — копия) |
| `keys(scope, prefix) -> {key = value}` | ключи области с префиксом (`nil` = все) |
| `on_change(scope, prefix, fn \| nil)` | `fn(key, value, old, by_peer)`; для `"object"` пятый аргумент — id объекта; `nil` снимает подписку |
| `handler(name, fn \| nil)` | хост: `fn(peer, args) -> ok, result` — обработчик запросов |
| `request(name, args, fn \| nil)` | кто угодно: обработчик хоста, ответ — `fn(ok, result)` |
| `broadcast(name, args, opts) -> true, machines` | хост: эффект всем (`nil`), одному (`{to = peer}`) или в радиусе (`{pos = vector, radius = m}`); хост — тоже получатель |
| `on(name, fn \| nil)` | `fn(args, from)` — эффект пришёл |
| `near(peer, obj_id, dist)`, `owns(peer, item_id)`, `in_container(peer, item_id, box_id)` | проверки для обработчиков хоста: персонаж игрока рядом, предмет у него, предмет в ящике рядом с ним (15 м) |
| `limit(name, burst, per_sec)` | хост: частота запросов `name` от одного игрока; по умолчанию 20 подряд, затем 10 в секунду |
| `export()`, `import(t)` | хост: сейв (`coop_sync.script`); моду не нужны |

Тексты отказов `set`:
- `"bad scope"`, `"bad key (1..128 bytes)"`;
- `"bad value: ..."` — что именно не так;
- `"value too large (N > 16384)"`;
- `"not allowed"` — эта машина не пишет эту область;
- `"no such object"`, `"no such player"`, `"another player's scope is the host's"`;
- `"scope full"`;
- `"too many changes waiting for the host"` — у клиента 4096 изменений без ответа.

Ответы запроса, если обработчик не дошёл до своего результата:
- `false, "no handler"`, `"rate limited"`, `"busy"`;
- `"not in the world"` — игрок ещё загружает мир;
- `"handler error"` — ошибка в обработчике (её трассировка — в логе хоста, сессия продолжается);
- `"bad result: ..."` — обработчик вернул то, что нельзя передать;
- `"timeout"` — нет ответа 30 с;
- `"session ended"`.

### 2.5 Гарантии и время
- Всё идёт одной упорядоченной полосой (Reliable). Изменения приходят в том порядке, в каком хост их принял.
  Ответ на запрос приходит после изменений, которые обработчик успел сделать.
- **Вход игрока.** Перед миром хост шлёт ему полную копию: world, session, все объекты, его собственную область игрока.
  Изменения после копии приходят следом. Чужие области игроков клиент не получает никогда.
- `on_change`, ответы и эффекты вызываются **в следующем кадре**, не внутри `set` / `request`. У клиента — только когда
  он уже в мире.
- Полная копия при входе и `import` событий `on_change` не вызывают. Скрипты нового мира читают состояние сами
  (`get` / `keys`) — например, в `actor_on_first_update`.
- Данные из сети проверяются по типу и размеру до передачи в Lua.
- Ошибка в обработчике или подписке пишется в лог и считается, сессия не рвётся.
- Lua-функции живут, пока жив Lua-стейт: после загрузки сейва подписки и обработчики регистрируются заново (обычно в
  `on_game_start`).
- Счётчики: `coop_status`, строки `[coop-sync]`. Там видно:
  - ключи и байты по областям;
  - отказы по причинам;
  - запросы: принятые, отказы, ошибки обработчиков;
  - рассылки;
  - ошибки Lua.

### 2.6 Сейв
`gamedata\scripts\coop_sync.script`:
- у хоста в `save_state` кладёт `coop.sync.export()` в `m_data.coop_sync`;
- в `load_state` отдаёт его `coop.sync.import()`;
- в `on_game_start` очищает данные прошлого мира — у новой игры нет `load_state`.

Область `session` не сохраняется. Клиент ничего не сохраняет и не загружает.

### 2.7 Примеры
```lua
-- данные предмета: пишет тот, кто его держит, видят все
coop.sync.set("object:" .. item:id(), "mag", { rounds = 30, kind = "ap" })
coop.sync.on_change("object", "mag", function(key, value, old, by_peer, id) refresh_icon(id, value) end)

-- действие через хост с проверками
if coop.is_host() then
	coop.sync.handler("hf.place", function(peer, args)
		if not coop.sync.owns(peer, args.item) then return false, "not yours" end
		if not coop.sync.near(peer, args.item, 3) then return false, "too far" end
		-- хост делает изменение штатными функциями: alife_create, transfer_item ...
		return true
	end)
end
coop.sync.request("hf.place", { item = coop.to_host_id(obj:id()) }, function(ok, why) if not ok then news(why) end end)

-- эффект для всех рядом
coop.sync.broadcast("fx.flare", { x = 1 }, { pos = pos, radius = 100 })
coop.sync.on("fx.flare", function(args, from) play_flare(args) end)
```

## 3. Декларации в ltx

Мод без патча описывает себя файлом `configs\coop_compat_<мод>.ltx` в нашем моде или DLTX `mod_coop_*.ltx`.
- Действует, только если мод установлен.
- Правило для скрипта, которого нет, ничего не меняет.

| Файл | Что объявляет |
|---|---|
| `coop_route.ltx`, `coop_route_*.ltx`, `coop_compat_*.ltx` | где исполняется обработчик колбэка: `host`, `owner`, `view`, `none`, `level`; секции `[route_scripts]`, `[route_callbacks]`, `[route_callbacks_forced]`, `[route_pairs]`, `[route_none_functions]` (описание — в шапке `coop_route.ltx`) |
| `coop_money.ltx` | хост: допуски денег, которые клиент получает сам, порог цены апгрейда |
| `coop_spawn.ltx` | хост: что клиент может попросить создать |
| `coop_settings.ltx` | какие опции решает хост, а какие — каждый игрок |
| `coop_mirror.ltx` (F2 T15) | ключи `m_data`, которые не зеркалятся клиентам |

## 4. Проверка мода без игры

Lua-тесты в `tests\lua\` (`tools\test_lua.cmd`) работают на заглушках движка.

`tests\lua\support\fake_sync.lua` — `coop.sync` на нескольких машинах в одном процессе, с правилами и числами движка:
- `fake_sync.machines()` → `host, client`;
- `fake_sync.as(machine, fn)` — код идёт от имени этой машины;
- `fake_sync.pump()` — доставка сообщений и вызов колбэков;
- `fake_sync.spawn/give/destroy` — предметы и их владельцы.

`install_sync_stubs(coop)` (`stubs.d\sync.lua`) даёт рабочий `coop.sync` одной машины. Пример —
`tests\lua\test_sync_shim.lua`.
