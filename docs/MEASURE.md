# Замер: цифры вместо догадок

Оптимизация принимается только с замером до и после (HOT-1). «Оптимизировано» — это та же игра для игрока: ни задержки,
ни тайминга, ни порядка, ни звука не меняется, а цифра стала меньше. Без цифры пишем «не проверено».

Каждый режим меряем отдельно: у хоста Коопа, клиента, сервера мира и сервера карты разная работа за кадр.

## Три инструмента

| Инструмент | Сборка | Что даёт | Цена, когда выключен |
|---|---|---|---|
| Таймеры движка (`rs_stats on`, `coop_mapserver_stats`) | обычная Release-AVX | кадр: среднее и худшее, части кадра по таймерам движка | одна проверка флага в CStatTimer |
| Lua-замер `coop_route.timing` | обычная Release-AVX | вызовы и время каждого обработчика колбэка и каждой функции, которую модуль внёс в свой `timing_sites` (обёрнутые функции модов) | одна проверка upvalue в обёртке колбэка; остальные функции — те, что у игры |
| Зоны Optick (`PROF_EVENT`) | ProfiledDX11 | дерево кадра с нашими функциями C++ | ничего: в Release-AVX макросы пустые |

### Таймеры движка

Консоль: `rs_stats on`, затем `coop_mapserver_stats`. Строки в журнале:

- `[coop] coop_mapserver_stats: private … MB, working set … MB, lua … MB, alife … objects, … online, frame avg … ms, worst … ms, … frames`
  — с прошлой строки;
- `[coop] coop_mapserver_stats: frame parts, ms: engine … (scheduler …, objects …, physics …, ai think …, …), render … (…); fps …`
  — сглаженные значения таймеров движка. Весь кадр нашего кода сидит внутри `engine` (стоковый `CGamePersistent::OnFrame`);
  отдельной строки у него пока нет.

### Lua-замер

`coop_route.timing(true)` включает и начинает новое окно, `coop_route.timing(false)` выключает (окно кончается),
`coop_route.timing_reset()` начинает новое окно,
`coop_route.print_timing(n)` печатает первые n по времени и по числу вызовов. `coop_status` печатает первые 10, пока у
какого-нибудь счётчика есть вызовы. Строки:

```
[coop-route] timing on, window 150.0 s
[coop-route] timing by ms #1 route actor_on_update@<script>: 812.300 ms, 9000 calls, 90.26 us/call, 5.415 ms/s, 60.0 calls/s
[coop-route] timing by calls #1 mods <метка обёртки>: 12.100 ms, 40000 calls, 0.30 us/call, 0.081 ms/s, 266.7 calls/s
```

Группы: `route` — обработчик колбэка, ключ `<колбэк>@<скрипт>` (как у счётчиков пропусков движка); `mods` — функция, которую
заменил `coop_mods_core.wrap`, ключ — её метка; `mode` — функции, которые `coop_mode` внесёт в свой `timing_sites` (вопросы
`where`, `leads_here`, `writes`, …; пока не внесены).

`timing_sites` — таблица модуля `{ [таблица] = { [имя функции] = метка } }` со слабыми ключами. Замер читает её у модулей
из своего списка (`coop_mods_core` → `mods`, `coop_mode` → `mode`) в момент включения.

Что надо знать, читая цифры:

- Часы — `profile_timer` движка (такты процессора). Время функции включает всё, что она вызвала: обработчик, который зовёт
  `coop_mode.leads_here`, несёт и его время.
- Пока замер включён, каждый вызов идёт через `pcall`, счётчик и два вызова `profile_timer`: у этого своя цена (её ещё не
  мерили). Сравнивать числа одного прогона между собой можно, сравнивать мс/с с прогоном без Lua-замера — нет.
- Функции из `timing_sites` подменяются в своих таблицах, пока замер включён. Код, который запомнил
  функцию в локальной переменной до включения, не считается. Обёртка, сделанная поверх подменённой функции, после
  выключения остаётся с ней (её счётчик продолжит считать).
- Ошибка обработчика под замером: та же ошибка поднимается снова (`error(e, 0)`); на хосте трасса стека начинается с
  замера, а не с места ошибки.
- Счётчик `coop.players()`, предметов `item_state` за кадр, `get_visible_value`, `CreateTimeEvent` и прирост
  `collectgarbage("count")` здесь пока не считаются.

Включить без консоли: ключ `-coop_perf_lua` вместе с `-coop_perf` (зонд `tools\stand\coop_zz_perf.script` включает замер в
момент, когда начинается окно кадра). Консольной команды пока нет.

### Зоны Optick

Сборка `ProfiledDX11` (решение `engine-vs2022.sln`) кладёт всё в свой каталог `engine\_build\_game_profiled\` (exe
`bin_dbg\AnomalyDX11.exe`), релизную сборку не трогает (`Common.props`, `xrGameDir` для конфигураций `Profiled*`).
Собирает ведущая, когда игра владельца закрыта; exe с библиотеками кладут в копию `bin` стенда, никогда в игру, mo2 или
`E:\Programs\RayLink`. Optick GUI той же версии, что `3rd party\optick-git`, подключается к exe по TCP; окно захвата 10–20 с.

Зоны нашего кода называются `coop/<файл>/<функция>`: проходы кадра (`coop/coop_sync/frame` и вызываемые из него
`frame`), рассылка хоста (`coop/coop_objects/host_stream`, `coop/coop_events/host_flush`), разбор у клиента
(`coop/coop_objects/client_*`), звук (`coop/coop_sound/lua_frame`), кадр слоя Сервер (`coop/coop_srv_mode/*::frame`,
`coop/coop_mapserver/*`, `coop/coop_levels_xfer/*`, `coop/coop_dedicated/frame`). Сверхчастые мелкие функции
(`l_runs`, `l_note`, `is_remote_creature`, `binder_action`) не размечены: зона стоила бы дороже их самих; их цена —
число вызовов из Lua-замера × микротест.

В ProfiledDX11 нет AVX и LTCG (ни у одного проекта этой конфигурации, `xrCoop` тоже): мелкие функции, которые релиз
встраивает, здесь видны отдельными вызовами. Смотрим доли и разницу до/после в одной сборке, а не абсолютные мс против
Release-AVX.

## Протокол

Одно и то же сохранение, людное место (много NPC рядом), 20 с прогрева, окно 150 с, 3 прогона на каждую роль. Сценарий —
`tools\stand\perf.ps1`; журналы он кладёт в рабочую папку стенда под именами `<Tag>_perf_<режим>_<роль>.log` и сам печатает
нужные строки.

| Режим | Роль | Как |
|---|---|---|
| Кооп | хост | `perf.ps1 -Mode coop -Save <stem> [-Lua] -Tag run1`: хост — профиль `appdata_t` с его сохранением, строки `host` |
| Кооп | клиент | тот же прогон, строки `client` (профиль `appdata_p` из `appdata_t`, без сохранений и ключа) |
| Сервер | клиент | `perf.ps1 -Mode server [-Save <stem>] [-Lua] -Tag run1`, строки `client` |
| Сервер | сервер мира | тот же прогон, журнал `world`. У процесса нет актора, зонд в нём не тикает: команды `rs_stats on`, `coop_mapserver_stats`, `coop_status` — с консоли сервера (не проверено) |
| Сервер | сервер карты | журнал в профиле, который ему создал сервер мира; ключи `-coop_perf` до него не доходят — команды с его консоли, если она доступна (не проверено) |

Второй клиент Коопа в протоколе — вторым запуском клиента с профилем `appdata_q` (сценарий пока запускает один).

Прогон с `-Lua` и без него — разные прогоны: таймер Lua сам стоит времени. Сначала прогоны без `-Lua` (кадр), потом с ним
(кто внутри кадра).

## Первые 10 гипотез (что проверить замером до любой правки)

1. `item_state`: обход всего инвентаря каждый кадр (`coop_mods_item_state.script` `capture_inventory`).
2. Вопросы `coop_mode` (группа `mode` Lua-замера, когда `coop_mode` внесёт их в `timing_sites`): число в секунду × цена вопроса.
3. Цена обёртки `coop_route` вокруг обработчика.
4. Обёртка `get_visible_value` на хосте.
5. Объём предикатов luabind (`api.is_active` и подобные).
6. Копии списка игроков (`coop.players()`, `Session::peers()`).
7. Обработчики на каждого NPC (маскировка, миражи, тревога у трупа).
8. Выделения в снимках и рассылке 15 Гц (хост, сервер карты: `coop/coop_objects/host_stream`).
9. Маршрутизация биндеров клиента.
10. Обход областей `CreateTimeEvent`.

Оптимизируем только то, что стоит больше ~0,1 мс за кадр или даёт пики. После каждой правки — тот же протокол и тесты
обоих режимов; в отчёте — цифры до и после по каждой роли.
