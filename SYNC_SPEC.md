# Anomaly Coop — спецификация синхронизации (v1, 2026-10-20)

Как игроки видят один и тот же мир. Документ описывает целевую модель; где текущий код отличается — помечено
«сейчас». Общая архитектура — `DESIGN.md` §10, правила поведения — `SPEC.md`.

## 1. Принципы

1. **Хост авторитетен.** Мир живёт на хосте: ALife, NPC, сюжет, время, физика. Клиенты получают результат.
2. **Синхронизация — работа движка.** Всё, что должно совпадать на всех машинах, передаёт C++. Lua никогда не
   изобретает свой сетевой протокол.
3. **Lua говорит «что», движок — «как».** Стоковая Lua-логика Anomaly и патчи модов описывают, какие данные общие
   и кто их меняет, и вызывают функции синхронизации движка (§6).
4. **Состояние, а не события, где можно.** Последнее значение важнее истории: опоздавшее или повторное сообщение
   не ломает картину (P5).
5. **Ничего не теряется и не приходит раньше времени.** Изменения для игрока, который ещё грузится, копятся и
   доставляются после загрузки (P6).
6. **Одни id на всех машинах.** Клиент грузит сейв хоста, id совпадают; единственное исключение — актор ↔ прокси,
   движок переводит его сам (`to_host` / `to_local`). Lua и сеть всегда работают в нумерации хоста.
7. **Клиенту не доверяем.** Любой запрос клиента проверяется на хосте: кто, что, где, сколько, как часто.

## 2. Транспорт и сессия (C++, `xrCoop`)

- ENet, три полосы: **Reliable** (упорядоченно, гарантированно), **Unreliable** (снимки, последнее важнее),
  **Bulk** (мир при входе, большие блоки с CRC).
- Сессия: рукопожатие (версия протокола, сборка, отпечаток модлиста), ключ игрока (`coop_player.key`), ник,
  фазы `off → connecting → handshaked → receiving-world → loading-world → live`.
- Живость: тишина 10 с — отвал; на время загрузок и сейвов поток keep-alive держит соединение (W9).
- Переполнение очереди игрока, который не может догрузиться, — кик с причиной.

## 3. Кто что решает (авторитет)

| Что | Решает | Как доходит до остальных |
|---|---|---|
| Существование объектов (спавн, удаление), онлайн/офлайн | хост (ALife, ближайший игрок) | события мира (§4.2) |
| NPC и монстры: ИИ, движение, анимации, смерть | хост | снимки 15 Гц + события; на клиентах куклы |
| Голоса и звуки NPC | хост | ретрансляция звуков в радиусе слышимости |
| Персонаж игрока: позиция, взгляд, анимации, оружие в руках, фонари | владелец (сам игрок) | снимки 20 Гц + PlayerEquip |
| Здоровье, потребности, ранение игрока | владелец; урон от мира считает хост | PlayerHit от хоста, состояние — от владельца |
| Кто держит предмет (владение) | хост | запрос → проверка → событие Parent |
| Внутреннее состояние своего предмета (патроны, прочность, апгрейды) | владелец | ItemState, хост держит копию |
| Деньги игрока | хост; клиент шлёт изменения с причиной, хост проверяет | ReqMoney → MoneyBalance |
| Торговля | хост, атомарная сделка | TradeOp |
| Диалоги | у говорящего; хост блокирует NPC на время разговора | DialogLock |
| Сюжет: инфопорции, задания, отношения, метки КПК | хост | реплицируемое состояние + сверка хешем |
| Время, погода, выброс, пси-шторм | хост | TimeSync / WeatherSync / фазы |
| Физика, двери, аномалии, взрывы | хост | EntityState / ZoneState |
| Настройки геймплея (сложность, экономика, MCM-опции мира) | хост | оверлей настроек у клиента |
| Данные модов | по объявлению патча мода (§6) | функции синхронизации движка |

## 4. Механизмы синхронизации (движок)

### 4.1 Снимки (Unreliable, последнее значение)
Игроки 20 Гц с задержкой интерполяции 100 мс; существа 15 Гц, анимации по частям тела; физика — сэмплы в движении
и итоговая поза в покое (Reliable). Пропуски не страшны, порядок по номеру.

### 4.2 События мира (Reliable, упорядоченные)
Спавн, удаление, смена владельца, смерть, онлайн/офлайн. Если объекта ещё нет — ожидание с таймаутом и запросом
к хосту (P3). Любое событие, которое делает объект свободным без EntitySwitch, обязано обновить онлайн-набор
клиента (урок 2026-10-20).

### 4.3 Запросы к хосту
Клиент не меняет мир сам: его игра шлёт действие в `CLevel::Send`, маршрутизатор превращает его в запрос, хост
проверяет и применяет, результат приходит всем событием. Отказ — ответ с причиной.

### 4.4 Реплицируемое состояние
Ключ → значение с версией; меняет только владелец ключа; полная копия при входе, дальше изменения; периодическая
сверка хешем и досылка. Так живут сюжет, настройки, и так же должны жить данные модов (§6).

### 4.5 Вход и догоняние
Хост сохраняет мир, клиент грузит сейв (`.scop` + `.scoc`), смена ролей актор ↔ прокси, затем живой поток; всё,
что произошло за время загрузки, приходит из очереди.

## 5. Жизненный цикл
- **Вход** нового игрока: создаётся персонаж-прокси (стартовый набор по группировке), вернувшийся — получает свой.
- **Выход/отвал**: персонаж уходит из мира и хранится в сейве хоста; возврат — на том же месте (W9).
- **Смена уровня**: сейчас — голосование за переход, хост переходит, клиенты перезагружают мир хоста. Цель
  (2026-10-22): каждый переходит сам, офлайн всех карт у хоста, онлайн карты считает ПК игрока на ней
  (`docs/SPLIT_LEVELS.md`).
- **Сейв/загрузка хоста**: клиенты получают SessionReset и перезагружают мир (счётчик поколений мира).
- **Конец сессии**: у клиентов чужие персонажи уходят из мира.

## 6. Функции синхронизации для Lua (новое; для стоковой логики и патчей модов)

Цель: патч мода объявляет, какие данные общие, и не пишет сетевой код. Справочник для мододелов — функции,
области, лимиты, тексты отказов и гарантии — `docs/COOP_API.md`; реализация — `coop_sync_api.cpp` (F2 T14).
Протоколы `coop_mods_*` и W4 поверх `coop.send_event` переходят на этот API в задачах Ф2 T16–T23.

Этот API — крайний случай. Сначала моды работают через слой модов без патчей: маршрутизатор колбэков,
маршрутизатор вызовов, зеркало `m_data` и декларации в ltx (`docs/MOD_LAYER.md`, решение 2026-10-22).

### 6.1 Общие переменные
```
coop.sync.set(scope, key, value)        -- меняет, если этой машине можно
coop.sync.get(scope, key) -> value
coop.sync.on_change(scope, key_prefix, func(key, value, old, by_peer))
```
Области (scope):
- `world` — общее для всех, меняет только хост, **сохраняется в сейв хоста**;
- `player` — данные конкретного игрока, меняет он сам (хост проверяет формат), хост хранит их по ключу игрока
  в своём сейве и возвращает при входе;
- `object:<id>` — данные, привязанные к объекту/предмету; уходят вместе с объектом (переход в другой инвентарь,
  выброс), удаляются с ним;
- `session` — общее на время сессии, не сохраняется.
Значения: число, строка, bool, вектор, плоская таблица; ключ до 128 байт, значение до 16 КиБ (Ruling F2-25), лимит
на область; движок переводит id объекта в имени области, id внутри значений — нет.

### 6.2 Действия через хост
```
coop.sync.handler(name, func(peer, args) -> ok, result)   -- регистрирует хост
coop.sync.request(name, args, on_result)                   -- вызывает кто угодно
```
Хост вызывает обработчик, проверяет права готовыми помощниками (`coop.sync.near(peer, obj_id, dist)`,
`coop.sync.owns(peer, item_id)`, лимит частоты на имя), результат возвращается вызвавшему; изменения мира делает
сам хост штатными функциями (`alife_create`, `transfer_item` …), и они расходятся обычными событиями (§4.2).

### 6.3 Эффекты для всех
```
coop.sync.broadcast(name, args, opts)   -- хост → всем / одному / в радиусе; только визуал и звук
coop.sync.on(name, func(args, from))
```

### 6.4 Зеркало состояния модов
`m_data` (колбэки `save_state` / `load_state`) и хранилище объектов (`se_save_var`) хост зеркалит клиентам
разницей по ключам верхнего уровня. Клиент получает полную копию при входе (`.scoc`), дальше — изменения.
Подробно — `docs/MOD_LAYER.md` §2.4.

### 6.5 Гарантии
Порядок внутри области сохраняется; всё объявленное догоняет вошедшего игрока; данные из сети проверяются по
типу и размеру до передачи в Lua; ошибка в Lua-обработчике не рвёт сессию; счётчики видны в `coop_status`.

## 7. Что где живёт

| Слой | Содержание |
|---|---|
| Движок (C++) | транспорт, сессия, вход/выход, мир (ALife, объекты, NPC-куклы, физика, зоны), игроки (снимки, урон, ранение), предметы и владение, торговля, диалоги, сюжет, время/погода, функции синхронизации для Lua (§6) |
| Lua — клей к стоку | патчи стоковой логики Anomaly, чтобы она понимала нескольких игроков (рестрикторы, встречи, задания, награды), прокладка маршрутизатора колбэков над `axr_main` (`coop_route.script`; решает движок), клиентские ограничения |
| Lua — интерфейс | меню «Кооператив», окно персонажа, чат, панель группы, метки союзников, опции |
| Движок — слой модов | маршрутизатор колбэков и вызовов, зеркало `m_data`, декларации ltx (`docs/MOD_LAYER.md`) |
| Lua — патчи модов | только если слоя модов не хватило: общие данные и обработчики через §6; включаются, только если мод установлен (MO2) |

## 8. Перенос из текущего Lua в движок / на §6
- маршрутизация заданий (кто взял, кто сдал, награда) — сейчас события в `coop_tasks`;
- деньги между игроками, данные предметов (`se_store`, «наездники» предметов), данные игроков — сейчас `coop_economy_*`;
- данные игроков модов (`coop_mods_pdata`) и все протоколы `coop_mods_*` — переписать на §6.1/§6.2;
- синхронизация секций логики рестрикторов (`npc.logic`) — на `world`/`object` переменные.

## 9. Защита и производительность
Каждое сообщение клиента — проверка роли, прав, дистанции, чисел (NaN, диапазоны), частоты; лимиты на очередь,
размер, число объектов в снимке; бюджет кадра на хосте (снимки по дальности, частота по важности).
